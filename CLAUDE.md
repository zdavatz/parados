## Project

Parados is a collection of standalone web board games by Walter Prossnitz, served as static files from `/var/www/game.ywesee.com/parados/` at `game.ywesee.com/parados`. Each game is one self-contained `.html` file (markup + `<style>` + `<script>`). No build, no package manager, no test framework, no dependencies. To run: open the file in a browser.

`index.html` is the landing page. **Light/dark toggle (2026-08-14):** a ☀️/🌙 `#theme-toggle` compact bright-gold pill in the **footer** (moved there from a fixed top-left placement that was too big and, on iOS, hid under the status-bar/notch). Dark is the DEFAULT (original look); light is a `:root[data-theme="light"]` override of the page's existing tokens (`--bg --card-bg --card-hover --accent --text --text-dim --desc --border`) — the gold `--accent` darkens to `#b8860b` for contrast on light, the coloured launch buttons stay unchanged. `<head>` script applies the theme before paint. **GLOBAL theme via the shared `localStorage["parados_theme"]` key (Zeno, 2026-08-14 — "go global"):** index.html AND every themeable game read/write the SAME key, so a toggle anywhere propagates to the others **on their next load** (verified bidirectional index↔MAKA LAINA↔DL remote via a Playwright cross-page test). **Each page keeps its own default-when-unset** (index + DL remote = dark, MAKA LAINA = light — unchanged first-visit look); once the key is set, all themeable pages follow it. **Themeable games (all read/write `parados_theme`):** MAKA LAINA (6 local), DL remote (6), **local DL (6), kangaroo (6), capovolto (6), democracy (6 local), frankenstein (6), rainbow_blackjack (6 local)** — the last five rolled out 2026-08-14 via parallel agents, same conservative surface-only pattern (dark-default kept; only page bg / panels / primary text / borders themed; all game-state colours — pieces, boards, canvas draws, highlights, coloured buttons — left hardcoded). `democracy_remote`×6 + `rainbow_blackjack_remote`×6 were themed too (2026-08-15, same connect-screen-remote pattern as DL remote — toggle in the header, reachable in-game). **Only `makalaina_remote` stays unthemed** (already a dark-only design). So EVERY game + the launcher is now theme-aware except that one remote. Verified per game: syntax-clean, the agent's ADDED theme code byte-identical across each game's variants (git-diff isolation, immune to pre-existing per-variant game-code differences like kangaroo's cn/ua/it), and a live headless test confirming each game follows the shared key on load + toggles + 0 errors. **Verification tip:** whole-file acorn structcmp is confounded by pre-existing localization JS differences (kangaroo cn/ua/it, frankenstein_it's reordered `name`, DL ua turn-indicator) — verify the *added* code via git-diff-of-added-lines-modulo-labels instead. The three formerly-separate keys (`index_theme`/`ml_theme`/`dl_theme`) were migrated to `parados_theme`.

## Architecture

- **Single-file pattern** per game.
- **Localization by duplication:** language variants are separate files (e.g. `kangaroo.html` DE, `kangaroo_en.html`, `_jp`, `_cn`, `_ua`, `_it`). When changing game logic, propagate to all variants.
- **Full localization — every game × 6 languages (Walter, 2026-08-09; DL remote added 2026-08-14):** all 11 game files (7 games + 4 `_remote` — democracy, makalaina, rainbow_blackjack, **and now divided_loyalties**) exist in **de / en / jp / cn / ua / it** = **66 game HTML files**, each with a rules PDF (`docs/rules/`, 66 PDFs). Italian was added and every prior gap filled (democracy/rainbow had only de+en; makalaina/frankenstein only en; capovolto only de; the remotes single-language). **Base-file language varies:** the unsuffixed file is DE for most, but EN for `frankenstein.html` and `makalaina.html`/`makalaina_remote.html` — so on the index/rules pages the "Deutsch" link points to `_de` for those two games and "English" to the bare file. **Method:** built by multi-agent workflow — each variant is `cp <source>` then display-strings-only translation, mirroring an existing sibling where one existed. **Invariants enforced & verified** (a regex-aware normalizer that blanks all string/template/regex contents proved JS logic byte-identical per file; the only accepted residue is grammar-driven reordering of `${…}` values *inside display templates*, empty-string quote style `""`↔`''`, and per-variant CSV/download `game` tags): slugs + embedded CSV `position_name` stay English; PeerJS protocol strings + embedded opening CSVs untouched; no `wa.me`; no `text:` beside `files:`; WhatsApp button label localized (DE `Auf WhatsApp teilen` · EN `Share on WhatsApp` · JP `WhatsApp で共有` · CN `分享到 WhatsApp` · UA `Поділитися у WhatsApp` · IT `Condividi su WhatsApp`). The Android/desktop apps auto-pull new variants via `index.html` links / their update lists — no rebuild for content.
- **Common JS shape:** `gameState` string state machine, 2D `board[y][x]`, `renderBoard()` + `initGame()`, `historyStack` + `undoMove()`, `localStorage` for prefs.

This subsumes (a) re-forming the same row, (b) extending a 3 to a 4 (existing 3 ⊂ new 4), and (c) overlapping 3-bridges along the same line — e.g. existing `[A,B,C]` + dropping `D` adjacent to `C` used to silently form a second `[B,C,D]` (visually a 4-bridge). - **Crossing/cover detection — GRID-EXACT, no floating point (Walter, 2026-06-02; "yellow and blue bridges cannot cut OR cover ANY other bridge, and red cannot cover other red"):** the float `ccw` segment test was scrapped — it kept missing through-stone crossings *and* (because of the 0.5-cell endpoint offset) some near-endpoint diagonal crossings, producing "yellow covers blue / yellow covers red" (both bridges drawn crossing, both still scoring). Replaced by an integer method:
  - `bridgeDoubledInfo(row)` maps a straight bridge to its **doubled-grid** occupancy: every **stone center** (doubled coords land on even,even) plus every **edge midpoint** between consecutive stones (carries an odd component). The two kinds can never collide, so a shared doubled point is unambiguous. Each point is tagged `{stone, end}` (`end`=one of the bridge's two endpoint stones).
  - `bridgesCrossedBy(newRow)` returns **every** active bridge the candidate crosses/covers. Conflict iff a shared doubled point is **(a)** an **edge midpoint** (→ a mid-gap diagonal crossing *or* a collinear cover) or **(b)** a **stone interior to BOTH** bridges (→ an X/+ through a shared stone). Legal (no conflict) only at a **junction**: a shared stone that is an **endpoint of at least one** bridge — fan-out, T, L, or end-to-end collinear (the 5-stone column). This exactly matches the **drawn** geometry (the 0.43-edge offset never reaches an edge midpoint), **verified by a brute-force harness: 0 mismatches across all 88,506 length-3/4 bridge pairs vs an independent exact segment-intersection oracle on the offset coordinates.**
  - `checkCollision(newRow, skipRed)` is now just "first conflict" over `bridgesCrossedBy` (scoring placement + dot highlight). **Red branch** (`tryFormBridge`): `bridgesCrossedBy(row)` → if any conflict is `cut` or `player==='red'` the whole placement is illegal (red can't cover red/cut, and **red is never cut by anything**); else `destroyBridge` **each** crossed scoring bridge. **Scoring branch:** any conflict → blocked. All call sites pass `row` (no offset coords needed for collision; `coords`/`c` is still computed only for `drawBridge`), so highlight ⟺ build.
  - **A perpendicular + through a shared *center* stone (interior to both) is BLOCKED for scoring** — this is the intended override of the older "perpendicular crosses are legal / single-stone overlap" notes. A stone may still anchor multiple bridges as long as they meet as **junctions** (endpoint-shared), not through-crosses. `sharesTwoPlus` (still upstream in `tryFormBridge`/`bridgeWouldForm`, skipping cut bridges) is now largely subsumed by the edge-midpoint rule but kept as an explicit "can't extend/re-form a row" guard.

## Share on WhatsApp button

Every game has a Share-on-WhatsApp button right of the `<h1>` (green `#25D366`, `gap:14px`).

**Button LABEL is localized per file language (Walter, 2026-06-30):** DE → `Auf WhatsApp teilen`, EN → `Share on WhatsApp`, JP → `WhatsApp で共有`, CN → `分享到 WhatsApp`, UA → `Поділитися у WhatsApp` (brand "WhatsApp" kept in every language). Applies to all share buttons in a file (rainbow_blackjack has 3). When adding a localized variant, set the button text to match `<html lang>`. (The DL share *dialog* heading + rules reference use the same localized term.) **Caution:** do the non-ASCII replacements with a UTF-8-safe tool (Python/Edit), NOT `perl -CSD -pe 's/…/<cjk>/'` — the literal in the `-e` program gets double-encoded into mojibake.

`shareOnWhatsApp()` flow:
1. If `window.location.protocol === "file:"`, rewrite to `https://game.ywesee.com/parados/<filename>` (WebView container paths are useless to recipients). **Keep this guard for any new game.**
2. Try `navigator.share({ text: msg })` first.
3. If `navigator.share` is missing, copy `msg` to the clipboard and `alert()` the user to paste it into WhatsApp. **NEVER `wa.me` (Walter, 2026-05-31).**

**No `wa.me/?text=` anywhere — text shares too (Walter, 2026-05-31):** the old fallback redirected to `whatsapp://send/?text=…` and Android WebView (and some in-app browsers) can't dispatch the scheme → `net::ERR_UNKNOWN_URL_SCHEME` ("Web page not available"). The replacement is the same pattern as file shares: try `navigator.clipboard.writeText(msg)`, fall back to a hidden `<textarea>` + `document.execCommand('copy')`, then `alert()` a localized "Message copied — paste it into WhatsApp" (DE/EN/JP/CN/UA per file `lang=`). If even the textarea copy fails, `prompt(note, msg)` shows the text so the user can long-press to copy. Applied to all 17 game files (`democracy×3`, `kangaroo×5`, `divided_loyalties×2`, `makalaina×2`, `capovolto`, `frankenstein`, `rainbow_blackjack×3`). The `navigator.share` short-circuit stays first so iOS/Mac/desktop browsers keep the native share sheet — only the no-share fallback changed.

For file shares (CSV / saved game JSON), use `navigator.share({ files:[file], title:'…' })` — no `text:`, no `wa.me` fallback. See divided_loyalties guardrails.
